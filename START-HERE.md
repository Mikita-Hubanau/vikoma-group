# VIKUB — с чего начать

## 1. Сравните оформления

Откройте сайт командой `npm run dev` после `npm ci`. Под переключателем языков
в шапке нажимайте **01–05**. Выбор меняет оформление всех разделов и сохраняется.
Основная версия открывается на итальянском; RU в шапке ведёт на русский.

Отдельно приложен `VIKUB-design-preview.html`: его можно открыть в браузере без
установки Node.js. Это **визуальный снимок из исходных шаблонов, не сборка Astro**.
Он использует системные запасные шрифты, позволяет переключать пять оформлений,
языки и разделы, но не проверяет сборку, CMS, оптимизацию ресурсов и реальные формы.
Дата в этом снимке зафиксирована до семинара; у настоящего сайта такого ограничения нет.
Не публикуйте этот HTML вместо собранного сайта.

## 2. Перенесите исходники

Архив `VIKUB-5-designs.zip` содержит полный проект. Распакуйте его отдельно,
не поверх единственной копии своих файлов. Затем в папке с `package.json`:

```sh
npm ci
npm run dev
```

Перед публикацией выполните `npm run build`. Здесь полная сборка Astro не
прошла проверку из-за отсутствия зависимостей; локальные тесты описаны в отчёте.

Второй способ — патч `VIKUB-revision-2.patch`. Он рассчитан **только на предыдущий
обновлённый архив `vikub-group-updated.zip`**, не на первоначальную версию GitHub.
Применять патч дополнительно к новому архиву не нужно.

```sh
git status
git apply --check /путь/к/VIKUB-revision-2.patch
git apply /путь/к/VIKUB-revision-2.patch
```

Если проверка не проходит, сохраните свои изменения и разберите различия;
не применяйте патч принудительно. Путь с пробелами заключайте в кавычки.

## 3. Подключите то, чего нет в ТЗ

Настоящие телефоны, email, LinkedIn и Telegram не предоставлены. В CMS
**Общее → Компания, контакты и партнёры** заполните эти значения для IT / EN / RU.
Адрес в Фано и контакт в Минске уже внесены. Неработающие ссылки не подставлены.

В **Общие подключения и служебное → Подключения** задайте публичный HTTPS-адрес
`registrationFormEndpoint` для регистрации и `contactFormEndpoint` для обращений.
При отсутствии отдельного адреса регистрации используется контактный обработчик.
Он должен различать запросы по `form_type` и принимать поля обеих форм.
Без обработчиков формы остаются выключенными — это не скрытая отправка на email.

Укажите свой GA ID, загрузите реальные фотографии/логотипы и добавьте утверждённую
политику обработки данных. Пароли и секретные ключи нельзя помещать в `PUBLIC_*`,
JSON или клиентский JavaScript.

## 4. Утвердите вариант оформления

`src/content/system/design.json` или CMS → **Оформление сайта**:
`defaultDesign` задаёт вариант первого визита, `showSwitcher` показывает кнопки.
Для сравнения оставлены `original` и `true`.

При отключении переключателя сохранённый выбор прежнего посетителя не стирается.
Для принудительного просмотра конкретного варианта используйте `?design=atlas`
или очистите настройку `vikub-design` в хранилище браузера.

## 5. Перед публикацией

Выполните `npm run build` и `npm run check:launch`, проверьте настоящую доставку
обеих форм, все 15 страниц и переключение языков. Дедлайн регистрации сохранён
из прежнего ТЗ: 28 сентября включительно по времени Италии.
Текст о ссылке за 3–4 дня до семинара — обещание организатора; автоматическая
рассылка Zoom-ссылок не реализована и требует отдельного процесса.

Подробности: `docs/LAUNCH.md`, `docs/DESIGNS.md`, `docs/TEST-REPORT.md`.
Ни GitHub, ни работающий сайт при подготовке файлов не изменялись.
