## Что открыть

`preview/VIKUB-layout-preview.html` — автономное интерактивное превью:
пять раскладок, IT / EN / RU, все пять разделов, мобильный режим.

Шрифты системные; формы и реальные внешние сервисы в нём не работают.
Нельзя публиковать его вместо проекта.

## Перенос проекта

Полный архив `VIKUB-branded-5-layouts.zip` содержит все исходники.
Распакуйте его в отдельную папку и используйте как новую рабочую версию.
Не помещайте весь архив в `public/` и не смешивайте старые HTML-превью.

Альтернатива — `VIKUB-brand-update.patch`, только поверх предыдущего
`VIKUB-Signature-5-layouts.zip`. Из корня распакованного проекта:

```sh
git apply --check /путь/к/VIKUB-brand-update.patch
git apply /путь/к/VIKUB-brand-update.patch
```

Не применяйте этот патч к более старым архивам или дополнительно к новому ZIP.
Сначала сохраните резервную копию своих локальных изменений.

## Запуск и сборка

Нужны Node.js 22.12 или новее и npm. Зависимости не обновлялись.

```sh
npm ci
npm run dev
```

Перед публикацией:

```sh
npm run build
npm run preview
```

В среде подготовки npm-реестр недоступен по DNS. `npm run build`
останавливается на проверке CMS из-за отсутствующего пакета `yaml`, до
компиляции Astro. Успешная полная сборка **не подтверждена**; отдельное
HTML-превью её не заменяет. Проверки перечислены в `docs/TEST-REPORT.md`.

## Логотипы

В шапке — `public/brand/vikub.svg`, исходный `VIKUB.svg` без изменения контуров
и цветов. В подвале — `vikub-on-dark.svg`: те же контуры и золото, графит
заменён на светлый для тёмного фона. Отдельная V использована для значка
вкладки и иконки устройства. Карточка для отправки ссылки также обновлена.
Подробности и размеры: `docs/BRANDING.md`.

## Раскладки

01 Signature, 02 Balance, 03 Editorial, 04 Atlas, 05 Panorama.
Кнопки остаются под языками. Все варианты используют один набор контента.
По умолчанию выбран Signature; выбор посетителя сохраняется.

`src/content/system/design.json`:

```json
{
  "defaultDesign": "signature",
  "showSwitcher": true
}
```

`showSwitcher: false` скроет кнопки сравнения. Текущее поведение выбора
раскладки при этом не изменяется: учитываются сохранённое значение и URL.

## Где править содержимое

Тексты страниц: `src/content/pages/{it,en,ru}/`.
Команда, эксперты, статус: `about.json`. Главный заголовок и кнопка контактов:
`home.json`. Партнёры, контакты, слоган и соцсети:
`src/content/settings/{it,en,ru}.json`.

Описания партнёров на главной и «О нас» выводятся одним компонентом
`PartnerGrid.astro`. Их не нужно редактировать в двух местах.
Полные адреса больше не выводятся; поле `address` оставлено пустым и скрыто
в CMS для совместимости. На сайте показываются только город и страна.

## Что нужно заполнить владельцу

Телефоны и email для Италии и Беларуси, реальные ссылки LinkedIn / Telegram
не предоставлены. Они пустые, интерфейс не ведёт на вымышленные профили.
У телефона заполняются и отображаемое `phone`, и `tel` в виде +кодномер.
Общие `email` / `phones` используются в подвале; при их отсутствии берутся
заполненные контакты офисов.

Для настоящей отправки сообщений нужен `contactFormEndpoint`. Для заявок
на семинар — `registrationFormEndpoint` либо совместимый общий обработчик.
Без него формы выключены; email в контактах не включает отправку автоматически.
Zoom-ссылки автоматически не рассылаются. GA4 ID и политика обработки данных
также требуют заполнения. Инструкция — `docs/LAUNCH.md`.
