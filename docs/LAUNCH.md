# Публикация обновления без Pull request

## Сайт

1. Распакуйте `VIKUB-Balance-update.zip`, откройте папку `UPLOAD`.
2. В репозитории выберите `main` и корень, где лежит package.json.
3. Add file → Upload files. Перетащите ВСЁ СОДЕРЖИМОЕ `UPLOAD`, не саму папку.
   Пути должны начинаться с src/, public/, tests/ и т. д., а не UPLOAD/.
4. Сообщение: `Apply Balance layout and detailed site brief`.
   Сохраните через Commit directly to the main branch → Commit changes.
5. Дождитесь НОВОГО успешного запуска «Публикация на GitHub Pages»: сборки,
   затем публикации. После завершения проверьте страницы и обновите Ctrl+F5.

Не удаляйте существующие папки. Не загружайте ZIP как файл сайта.
В архиве обновления менее 100 файлов для одной загрузки. Документы вне UPLOAD
в репозиторий переносить не нужно. Новая проверка HTML выполняется до публикации.

## PHP и письма — отдельный шаг

В предоставленном проекте обе формы настроены на
`https://vikub.com/api/contact.php` в src/content/system/integrations.json.
Переменные PUBLIC_CONTACT_FORM_ENDPOINT / PUBLIC_REGISTRATION_FORM_ENDPOINT
в Actions могут переопределять это значение; их содержимое в этой среде неизвестно.
Настройки и существующий workflow сохранены.

GitHub Pages обслуживает статические файлы и не выполняет PHP. При использовании
этого обработчика необходимо сохранить резервную копию на хостинге vikub.com,
затем заменить его `/api/contact.php` содержимым `public/api/contact.php` из проекта
(либо файлом api/contact.php из отдельного PHP-архива).
Пути хранения заявок, получатели, лимиты частоты и дедлайн регистрации сохранены.
Публичную папку с журналами создавать не нужно: хранение осталось вне сайта.

Новая версия сервера делает телефон обращения обязательным, сохраняет компанию
и тему, проверяет варианты тем и согласие. В регистрации телефон по-прежнему
необязателен. CORS разрешён только для https://vikub.com и
https://mikita-hubanau.github.io, без wildcard и передачи cookies.

Если используется другой обработчик (например, собственный внешний сервис),
ему также нужно принимать поля `company` и `service`; PHP-файл его не изменит.
После публикации отправьте одну реальную заявку и проверьте письмо/журнал,
затем отдельно регистрацию. Локальные тесты не отправляли настоящие письма.

Темы обращения редактируются в contacts.json. Их серверный список CONTACT_TOPICS
на PHP-хостинге должен совпадать; при изменении вариантов обновляйте оба места.
Срок регистрации и настройки семинара также должны совпадать на клиенте и сервере.

## Редактор и материалы

Публичные ссылки на редактор удалены, но /admin/ и настройки CMS сохранены.
Реальные фотографии и логотипы добавляются через CMS либо src/assets/media/;
точные поля перечислены в BRIEF-STATUS.md. Контактные тексты снова связаны с CMS.
Пустой audience не отображается; LinkedIn не ведёт на выдуманный профиль,
Telegram не отображается без ссылки.

## Команды проверки

```sh
npm ci
npm test
npm run check:site
npm run check:cms
npm run build
```

Новые postbuild-проверки анализируют настоящий dist. В среде подготовки сборка
Astro не подтверждена из-за недоступности npm, поэтому зелёный результат GitHub
Actions обязателен. Не считайте загрузку исходников равной успешной публикации.
