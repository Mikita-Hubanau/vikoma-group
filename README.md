# Vikoma Group — сайт-визитка

Статический сайт на Astro. Все страницы собираются заранее в обычный HTML,
поэтому сайт быстро открывается и его можно положить на любой хостинг —
достаточно скопировать папку с файлами.

## Где что лежит

```
site.config.mjs              ← домен сайта. Меняется только здесь

src/content/                 ← ВСЕ ТЕКСТЫ САЙТА
  settings/ru.json             общие: телефоны, почта, мессенджеры, офисы, реквизиты
  pages/ru/home.json           главная
  pages/ru/services.json       шапка страницы «Услуги»
  pages/ru/industries.json     шапка страницы «Отрасли»
  pages/ru/about.json          «О компании»
  pages/ru/contacts.json       «Контакты»
  services/ru/*.md             услуги — по файлу на каждую
  industries/ru/*.md           отрасли — по файлу на каждую
  system/blocks.json           каталог блоков (служебное)
  system/notfound.json         страница «не найдено» (служебное)

  Порядок «раздел, потом язык» — требование CMS. Рядом с ru/ лежат it/ и en/

src/assets/media/            ← ФОТОГРАФИИ. Сжимаются при сборке
public/media/video/          ← видеофайлы (не сжимаются)
public/admin/                ← редактор: панель и её настройки
src/data/map.json            ← контуры стран для карты (создаётся скриптом)
scripts/                     ← генератор карты и проверка настроек редактора

src/views/                   ← ВЁРСТКА СТРАНИЦ, одна на все языки
src/pages/                   ← только адреса: по 4 строки на файл
src/components/              ← блоки страниц
src/components/blocks/       ← библиотека готовых блоков
src/components/edit/         ← кнопки правки прямо на сайте
src/layouts/                 ← общая обёртка страниц
src/styles/global.css        ← цвета, шрифты, отступы — весь внешний вид
src/i18n/                    ← языки, адреса страниц, надписи интерфейса
```

Тексты отделены от вёрстки специально: их правит человек, вёрстку — разработчик.
Вручную в файлы лазить не нужно — для правки текстов есть редактор в браузере:
`/admin/`. Он же переводит тексты между языками по кнопке.

## Языки

Сайт на трёх языках: русский, итальянский, английский.

Адреса у каждого языка свои и заданы в `src/i18n/routes.ts`:

| страница    | RU              | IT               | EN                 |
| ----------- | --------------- | ---------------- | ------------------ |
| Главная     | `/`             | `/it/`           | `/en/`             |
| Услуги      | `/uslugi/`      | `/it/servizi/`   | `/en/services/`    |
| Отрасли     | `/otrasli/`     | `/it/settori/`   | `/en/industries/`  |
| О компании  | `/o-kompanii/`  | `/it/azienda/`   | `/en/about/`       |
| Контакты    | `/kontakty/`    | `/it/contatti/`  | `/en/contacts/`    |

Русский — основной, поэтому он в корне и без префикса.

Вёрстка страниц лежит в `src/views/` и общая для всех языков: правка дизайна
делается один раз, а не трижды. В `src/pages/` только адреса — по четыре строки
на файл, без разметки внутри.

Порядок языков в переключателе задаётся списком `enabledLocales`
в `src/i18n/config.ts`. Убрать язык с сайта = убрать его из этого списка;
тексты и страницы при этом остаются на месте.

**Итальянский и английский тексты сейчас черновые** — перевод русской
заглушки. Их нужно заменить вместе с русскими.

## Каталог блоков

Служебная страница `/blocks/` — все готовые блоки живьём, с пояснением,
когда каждый уместен и что для него нужно. В меню её нет, от поисковиков
закрыта, в карту сайта не попадает.

Сами блоки лежат в `src/components/blocks/`. Пока фотографий нет,
на их месте заглушка `MediaPlaceholder` с подсказкой, какой снимок нужен:
когда появится настоящее фото, блоку задаётся `src`, и заглушка исчезает
сама — вёрстку менять не нужно.

## Фотографии

Снимки лежат в `src/assets/media/`. В текстах на них ссылаются коротким
адресом — `/media/industries/oborudovanie.jpg`, — а связь с файлом
устанавливает `src/lib/images.ts`.

При сборке каждый снимок автоматически:

- сжимается и переводится в современные форматы AVIF и WebP;
- нарезается на пять размеров (400–1600 px), и браузер качает тот,
  что нужен его экрану;
- получает ширину и высоту, чтобы страница не дёргалась при загрузке.

Что это даёт: страница «Отрасли» вместо 560 КБ фотографий отдаёт
237 КБ на телефоне и 161 КБ на обычном мониторе.

Чтобы добавить фото — положите файл в `src/assets/media/` и укажите путь
в тексте. Если файла по указанному пути нет, сборка напишет об этом
в журнал и покажет заглушку.

Видео сжимать при сборке нельзя, поэтому файлы лежат в `public/media/video/`
и готовятся заранее.

## Страница «не найдено»

`src/pages/404.astro` — короткая фраза на трёх языках и ссылки на разделы.
GitHub Pages подхватывает её сам. Для обычного хостинга нужен `.htaccess`
из папки `public/` — он уже там и содержит строку `ErrorDocument`.

## Карта на первом экране

Очертания стран взяты из открытых данных Natural Earth и один раз
пересчитаны в готовую картинку. На сайте нет никаких карт-библиотек:
там лежит обычный рисунок весом около 12 КБ.

Пересобрать карту (например, чтобы добавить страну или подвинуть кадр):

```sh
npm run build:map
```

Что настраивается в начале `scripts/build-map.mjs`:

- `COUNTRIES` — какие страны рисовать и куда сдвинуть подписи
- `LINKS` — между какими странами вести дуги
- `FRAME_LON` / `FRAME_LAT` — какой кусок карты попадает в кадр
- `COORD_STEP` — насколько огрублять берег (больше = легче файл)

Подписи стран лежат не здесь, а в текстах: `hero.map.countries`
в `src/content/<язык>/pages/home.json`. Так они переводятся.

## Перенос на другой компьютер

**Для правки текстов ничего переносить не нужно.** Редактор работает
в браузере с любого устройства:

- сайт: https://mikita-hubanau.github.io/vikoma-group/
- редактор: https://mikita-hubanau.github.io/vikoma-group/admin/

При первом входе на новом устройстве редактор попросит ключ доступа:
нажмите «Sign In with Token», перейдите по ссылке на GitHub, создайте
ключ и вставьте обратно. Ключ хранится в браузере, поэтому на каждом
новом устройстве и в каждом новом браузере это делается один раз.

Всё остальное ниже — только если нужно менять код, а не тексты.

### Что переносить не нужно

Весь проект хранится на GitHub. На компьютере не остаётся ничего
незаменимого: папки `node_modules/`, `dist/` и `.astro/` создаются
заново из исходников.

### Настройка нового компьютера

**1. Node.js версии 22 или новее.** Обычный установщик с nodejs.org
требует пароль администратора. Если его нет — можно поставить
в домашнюю папку:

```sh
mkdir -p ~/.local
curl -o /tmp/node.tar.gz https://nodejs.org/dist/v24.19.0/node-v24.19.0-darwin-arm64.tar.gz
tar -xzf /tmp/node.tar.gz -C /tmp
mv /tmp/node-v24.19.0-darwin-arm64 ~/.local/node
echo 'export PATH="$HOME/.local/bin:$HOME/.local/node/bin:$PATH"' >> ~/.zprofile
```

Откройте новое окно Терминала и проверьте: `node --version`

**2. Забрать проект:**

```sh
git clone https://github.com/Mikita-Hubanau/vikoma-group.git
cd vikoma-group
npm install
```

**3. Запустить у себя:**

```sh
npm run dev
```

Сайт откроется на http://localhost:4321

### Если нужно выкладывать изменения с нового компьютера

Понадобится GitHub CLI и вход в аккаунт:

```sh
brew install gh    # либо скачать с cli.github.com
gh auth login
```

Отвечать: **GitHub.com** → **HTTPS** → **Yes** → **Login with a web
browser**. Код из терминала вставляется в браузере. Признак успеха —
строка `✓ Logged in as ...` в терминале, а не только надпись в браузере.

Без этого код заберётся и запустится, но отправить изменения обратно
не получится.

## Команды

```sh
npm run dev        # запустить сайт локально: http://localhost:4321
npm run build      # собрать готовые файлы в папку dist/
npm run build:map  # пересобрать карту стран на первом экране
npm run check:cms  # проверить настройки редактора
```

Нужен Node.js версии 22 или новее.
