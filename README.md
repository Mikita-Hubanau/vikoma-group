# Vikub Group — сайт на трёх языках

Обновление проекта `Mikita-Hubanau/vikoma-group` по предоставленному ТЗ.
Бренд сайта — **Vikub Group**, целевой домен — **vikub.group**.
Имя репозитория намеренно не менялось.

Сайт остаётся статическим проектом **Astro** с **Sveltia CMS**. Сохранены
существующая типографика, светлая палитра с терракотовым акцентом,
векторная карта и библиотека демонстрационных блоков.

**Важно:** это обновлённые исходники, а не уже опубликованный сайт. Настоящие
контакты, Google Forms, обработчик писем, GA ID и официальные логотипы
не были предоставлены. Они оставлены пустыми. Полная сборка Astro в среде
подготовки не выполнена из-за недоступности npm-зависимостей; детали —
в [отчёте о проверках](docs/TEST-REPORT.md).

## Быстрый запуск

Нужен Node.js, соответствующий `package.json` (не ниже 22.12.0).
В существующем GitHub workflow используется Node.js 24.

```sh
npm ci
npm run dev
```

Откройте локальный адрес, который напечатает Astro. Команду нужно выполнять
в папке с `package.json`.

Проверка и подготовка публикации:

```sh
npm test
npm run build
npm run preview
```

`npm run build` сначала проверяет CMS, структуру контента и выполняет тесты.
После успешной сборки папка `dist/` содержит сайт для статического хостинга.
Не подменяйте `npm ci` на обновление всех зависимостей: версии и lock-файл
сохранены из исходного проекта.

## Страницы

| Раздел | Русский | Italiano | English |
|---|---|---|---|
| Главная | `/` | `/it/` | `/en/` |
| О нас | `/o-kompanii/` | `/it/azienda/` | `/en/about/` |
| Услуги | `/uslugi/` | `/it/servizi/` | `/en/services/` |
| Мероприятия | `/meropriyatiya/` | `/it/eventi/` | `/en/events/` |
| Контакты | `/kontakty/` | `/it/contatti/` | `/en/contacts/` |

Русский остался языком по умолчанию, как в исходном проекте. Переключатель
RU / IT / EN находится в шапке и ведёт на тот же раздел другого языка.
В каждом меню ровно пять разделов. Блога нет.

Старые адреса `/otrasli/`, `/it/settori/`, `/en/industries/` перенаправляются
на услуги соответствующего языка. На статическом хостинге это страницы
перенаправления Astro, а не обещание серверного HTTP 301. Архивные тексты
отраслей сохранены в исходниках, но не выводятся в основном разделе/CMS.

## Где редактировать

Панель: `/admin/`. На GitHub Pages с подпапкой —
`/vikoma-group/admin/`. Авторизация и права на репозиторий должны быть настроены
в вашем окружении; реальный вход в CMS здесь не проверялся.

В редакторе:

- **Общее → Компания, контакты и партнёры** — бренд, офисы, телефоны, email,
  соцсети, партнёры, их названия, описания и логотипы.
- **Страницы** — тексты пяти страниц на русском, итальянском и английском.
- **Услуги — содержание** — пять услуг и их состав.
- **Общие подключения и служебное** — формы, Analytics, дата семинара,
  каталог блоков и страница 404.

Параметр `?edit=1` включает кнопки редактирования на сайте, `?edit=0` выключает.
Это удобный режим интерфейса, **не авторизация**. `/blocks/` — публичный
демонстрационный каталог с `noindex`, не защищённая паролем страница.
Демонстрационные фото, отзывы и имена из каталога не используются как
реальные материалы Vikub Group на основных страницах.

## Структура исходников

```text
site.config.mjs                    домен, SITE_URL и BASE_PATH
locales.config.mjs                 общий список языков
src/content/settings/{ru,it,en}.json
                                  контакты и партнёры
src/content/pages/{ru,it,en}/*.json тексты пяти страниц
src/content/services/{ru,it,en}/*.md
                                  пять услуг на каждом языке
src/content/system/integrations.json
                                  публичные ID/URL подключений
src/content/system/seminar.json    общие дата, время и срок регистрации
src/views/                        общая для языков вёрстка страниц
src/components/                   блоки, форма, аналитика
src/components/blocks/            сохранённая библиотека блоков
src/assets/media/                 изображения, загружаемые из CMS
public/scripts/                   браузерная логика форм/аналитики/семинара
public/admin/                     редактор и конфигурация его полей
scripts/                          проверки и подготовка публикации
tests/                            Node-тесты и изолированные браузерные тесты
```

Тексты на всех трёх языках заполнены по ТЗ. Перед публикацией рекомендуется
редакционная проверка переводов, имён и названий самими представителями компании.

## Подключения

Один файл для всех языков — `src/content/system/integrations.json`:

```json
{
  "googleAnalyticsId": "",
  "contactFormEndpoint": "",
  "registrationUrl": ""
}
```

Можно заполнить через CMS либо через публичные переменные
`PUBLIC_GOOGLE_ANALYTICS_ID`, `PUBLIC_CONTACT_FORM_ENDPOINT`,
`PUBLIC_REGISTRATION_URL`. Непустые переменные имеют приоритет над JSON.
Локальный `.env` можно создать из `.env.example`. Не коммитьте секреты.
Эти параметры применяются **при сборке**, а не после открытия готового HTML.

Форма рассчитана на HTTPS-обработчик, совместимый с обычным POST и JSON-ответом
`{"ok": true}` либо `{"success": true}`, например Formspree. Один лишь email
в контактах не включает отправку. При пустом endpoint форма выключена.
При сетевой ошибке текст не стирается; неизвестный ответ сервера не считается
подтверждением доставки. Нужна отдельная проверка получения письма в вашем ящике.

Analytics подключается только при заданном GA4 Measurement ID и согласии
посетителя. До согласия скрипт Google не вставляется. Отказ и отзыв согласия
поддерживаются; в футере есть настройки аналитики. Это техническая реализация,
а не юридическое заключение о соответствии требованиям к обработке данных.

## Семинар

В `src/content/system/seminar.json` заданы:

- 1 октября 2026, 11:00, `Europe/Rome`;
- продолжительность 120 минут;
- последняя разрешённая секунда регистрации —
  `2026-09-28T23:59:59+02:00`.

Фраза ТЗ «до 28 сентября» реализована как регистрация **включительно до конца
28 сентября по итальянскому времени**. Это выбранная интерпретация, а не
отдельно подтверждённое организатором условие; при необходимости измените срок.

Дата и продолжительность подставляются в переводы через `{date}` и `{duration}`.
После дедлайна регистрация скрывается, после окончания семинара показывается
статус завершения. В браузере состояние пересчитывается при открытии страницы,
возврате на неё и раз в 30 секунд. Без JavaScript используется состояние на
момент сборки, поэтому после изменения события стоит пересобрать сайт.
Время устройства посетителя влияет на браузерное отображение; окончательное
закрытие самой Google Forms нужно настроить у организатора отдельно.
